# Архитектура

- Тип: custom integration для Home Assistant; установка через HACS.
- Сущность weather нативная, никакой MQTT-обвязки.
- WIS2 stations — отдельный справочник с координатами; выбор ближайшей станции по большой окружности.
- WIS2 SYNOP — GeoJSON, по одной записи на показатель; данные объединяются **только внутри одного reportTime**.
- Контроль свежести по reportTime, а не по времени скачивания. Допускается возраст не больше четырёх часов.
- Автоматический выбор проверяет до восьми ближайших станций. Ручной режим не скрывает проблему переключением на другую.
- В случае потери данных сущность становится unavailable, а не публикует старые измерения как текущие.
- Влажность, давление, ветер, видимость и облачность опциональны — отсутствие не заменяется нулём.
- Прогноз WRF отдельно: запрещено включать поддерживаемые forecast features до документированной проверки формата JSON, единиц измерения, дат прогнозов и тестов.
- Вся обработка API асинхронная в общем aiohttp-сеансе Home Assistant. Обновление 30 минут.
- Отсутствуют телеметрия DigitalHouses, самостоятельный фоновый процесс и управляющие действия.

## Проверки на реальном HA (ещё не выполнены)

1. Сверить геометрию, идентификаторы станций и доступность API.
2. Убедиться, что фильтры WIS2 по WIGOS и datetime реально применяются (не игнорируются сервером).
3. Сверить reportTime и возраст реальных наблюдений по нескольким станциям Казахстана.
4. Проверить условия использования данных, HACS-загрузку, обновление и отработку ошибок API.
5. Выгрузить и изучить образец WRF JSON; только после этого проектировать дневной и почасовой прогноз.
