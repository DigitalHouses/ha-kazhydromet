# Архитектура

## Источники

- WIS2 OGC Features: станции и SYNOP. Результат каждого датчика с WIGOS и reportTime. Только данные одного отчёта объединяются в наблюдение.
- WRF JSON: 383 прогнозные точки, временной шаг 3 часа, примерно 9 суток. Точка выбирается по координатам HA независимо от WIS2-станции.
- Прогноз temp_blend — температура °C; precip_mm — мм за интервал; pressure_hpa — гПа; wind_speed — м/с; humidity_rel — %; cloud_fraction — доля 0..1.

## Контракты

- Запрещено выдавать устаревшие измерения за текущие: максимум 5 часов с reportTime.
- WRF — максимум 36 часов с generated_at; проверка схемы и единиц при каждом новом выпуске.
- Если измерение WIS2 недоступно, текущую температуру формирует модель WRF, **с отдельным явным сенсором источника**.
- Почасовой интерфейс Home Assistant отдаёт исходные 3-часовые точки без интерполяции.
- Суточный прогноз только для полных календарных локальных суток: 8 прогнозных отсчётов на день.
- Ни одна отсутствующая метрика не заменяется вымышленным нулём.
- Источник текущей погоды: машинные состояния `wis2_observation` и `wrf_model`, UI-переводы через `translation_key`. Публичные `unique_id` и `entity_id` сохраняются.
- В состояниях погоды осадки имеют приоритет над облачностью. Фаза (снег/дождь) оценивается только по температуре, поскольку отдельной фазы в WRF JSON нет.
- Суточный дождь учитывается в `condition`, даже если средняя облачность мала.
- Сумма суточных осадков выдаётся только если трёхчасовая сетка совпадает с границей локальных суток. В Алматы UTC+5 она не совпадает, поэтому суточные миллиметры остаются отсутствующими без допущений о распределении дождя внутри интервала.

## Ресурсы

- Наблюдения — обновление каждые 30 минут.
- Прогнозный JSON около 8.5 МБ — кеш 3 часа на экземпляр интеграции.
- Нет MQTT, фоновых процессов, телеметрии и дополнительных контейнеров.

## Открытые испытания

1. Запуск Config Flow на Home Assistant OS, изменение доступности двух API.
2. Нагрузочная проверка фильтра WIGOS/datetime и сценариев отсутствия данных.
3. Сравнение наблюдаемой и модельной температуры в HA Recorder.
4. Проверка доступности и лицензии API для коммерческой эксплуатации.
5. Проверка HACS / Hassfest, смены станции и обновления интеграции.
