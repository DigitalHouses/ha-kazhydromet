# Казгидромет для Home Assistant

Нативная интеграция Home Assistant с фактическими наблюдениями **WIS2 SYNOP** и прогнозом **WRF** Казгидромета. Установка через HACS, без MQTT, Supervisor App и отдельных контейнеров.

**Версия 0.1.0 (пилот).** Проверены запуск HAOS, получение фактических наблюдений, почасовые и суточные прогнозы. Испытания отказов API и перехода на HACS продолжаются.

## Возможности

- Нативная сущность weather с текущей температурой, влажностью, давлением, ветром, облачностью, видимостью (если доступны).
- Фактическая погода WIS2 по ближайшей станции с актуальными наблюдениями; ручной выбор WIGOS-станции.
- Прогноз WRF на ~9 суток с **шагом 3 часа**, выдаваемый стандартным почасовым API HA. Суточные минимумы/максимумы рассчитываются только для дней с полными восемью трёхчасовыми интервалами.
- Отдельные диагностические сенсоры времени наблюдения, станции, источника текущей температуры, времени выпуска WRF и прогнозной точки.
- Обновление наблюдений раз в 30 минут; большой WRF JSON кешируется на 3 часа.
- Проверка свежести: SYNOP — до 5 часов, WRF выпуск — до 36 часов; неверная структура и устаревшие данные отклоняются.

**Источники не смешиваются незаметно.** Если актуальных WIS2-измерений нет, текущая погода может вычисляться по WRF. Диагностика «Источник текущей погоды» показывает `wis2_observation` или `wrf_model` (в русскоязычном интерфейсе — «Наблюдения WIS2» или «Модель WRF»). Модельное значение не является измерением термометра.

У WRF доступен расчёт по ограниченному набору **383 прогнозных точек**, не точный прогноз на произвольные координаты. Берётся ближайшая прогнозная точка. Суточные экстремумы по 3-часовой сетке могут отличаться от реальных экстремумов между шагами.

**Состояния дождя/снега:** при прогнозируемых осадках они имеют приоритет перед облачностью. Фаза осадков оценивается по температуре (WRF не содержит отдельного признака снег/дождь). При публикации суточного условия учитываются все 8 интервалов, а не только средняя облачность.

**Суточная сумма осадков:** трёхчасовые интервалы WRF не совпадают с полуночью местного времени Алматы (UTC+5). Точный итог за локальные сутки из этих данных определить нельзя без интерполяции; поэтому HA не получает синтетическую суточную сумму. Значения `precipitation` в трёхчасовом прогнозе сохранены без изменений.

## Установка через HACS

1. HACS → меню ⋮ → Custom repositories.
2. Добавить https://github.com/DigitalHouses/ha-kazhydromet, тип **Integration**.
3. Установить Kazhydromet и перезапустить Home Assistant.
4. Настройки → Устройства и службы → Добавить интеграцию → Kazhydromet.
5. Выбрать автоматический поиск станции либо конкретную метеостанцию.

Если ранее интеграция была установлена вручную (через копирование `custom_components/kazhydromet`), сначала добавьте репозиторий в HACS и установите через **Download**, затем перезапустите Home Assistant. Существующую запись интеграции удалять и повторно создавать **не нужно**: HACS управляет файлами интеграции, а конфигурация остаётся в Home Assistant. Если HACS откажется перезаписывать существующую папку, сделайте её резервную копию и лишь затем повторите установку.

Названия диагностических сенсоров переводятся на **язык серверной конфигурации Home Assistant** при регистрации сущностей. Для уже зарегистрированных сенсоров могли сохраниться прежние английские `friendly_name`; это не меняет их `entity_id` или `unique_id`. Если в интерфейсе остались старые названия, проверьте язык Home Assistant и существующие переименования в реестре сущностей.

До завершения испытаний отказов API не используйте интеграцию для критических автоматизаций.
